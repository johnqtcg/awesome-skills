Confirmed verbatim from the live official PostgreSQL documentation. This is a well-established PostgreSQL behavior: `CREATE INDEX CONCURRENTLY` cannot run inside a transaction block (unlike a regular `CREATE INDEX`), because it needs to perform multiple internal transaction phases (catalog entry, table scans, waiting on other transactions) that aren't possible while already inside an explicit `BEGIN`/`COMMIT` block. Attempting it raises the error `ERROR: CREATE INDEX CONCURRENTLY cannot run inside a transaction block`. This also applies to related commands like `DROP INDEX CONCURRENTLY`, `REINDEX CONCURRENTLY`, and `REFRESH MATERIALIZED VIEW CONCURRENTLY`, and is why migration frameworks (Rails, Django, Flyway, etc.) require disabling the transaction wrapper for migrations that use it.
